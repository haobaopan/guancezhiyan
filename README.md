# 管策智研 · 政策文本研究助手

面向规划与政策文本的本地知识库问答工具：**检索 → 片段级溯源 → 证据校验 → 结构化输出 → 一键交付**。
只用 Python 标准库，双击即可在本机跑起来；不联网也能用（只是不生成综合结论）。

## 开发入口与源码导航

原 3090 行单体已拆入 `policy_core/`，同名 `应用源码_示例知识库版.py` 现在是兼容启动入口。后续修改先看 [源码导航与模块拆分](docs/源码导航与模块拆分_V1.md)，按功能直接定位模块；完整原版保存在 `backups/source_split_20261102_v1/`。

- 旧版：`应用源码_示例知识库版.py` → `policy_core/`，默认 8765，页面在 `policy_core/web/`。
- 登录注册与设置版：`应用平台_v2.py` → `app/`，默认 8766，页面在 `app/web/`，通过 `app/legacy.py` 复用 `policy_core/` 的检索、分析和导出。
- 本轮仅做职责拆分和必要接线。按用户要求，整套自检及浏览器验收延后；前一轮的 41 项通过记录不代表拆分后已经回归。

## 能做什么

| 能力 | 入口 | 说明 |
|---|---|---|
| 政策问答 | 「政策问答」页签 / `POST /api/ask` | 回答拆成最小事实主张，逐条对照原文校验，未通过的直接省略 |
| 四要素提取 | 「四要素提取」/ `POST /api/extract` | 量化目标 / 重点产业 / 政策工具 / 责任主体，表格输出，可导 Excel |
| 多文件比较 | 「多文件比较」/ `POST /api/compare` | 按文件分别对比目标、对象、举措、指标，不混淆归属 |
| 跨期演变 | 「跨期演变」/ `POST /api/evolution` | 同一地区同一主题按规划期（一五…十四五、政府工作报告）排序对照 |
| 多轮追问 | 直接接着问 | 「那它的量化目标呢」会自动继承上一轮的地区与主题 |
| 回看原文 | 点击任意证据 | 打开可读网页并**自动滚动 + 高亮**到该片段，顶部有「文件/章节/段落/片段」定位条 |
| 导出 | 导出 Word / Excel / CSV / PPT | Word 带页码与引用超链接，PPT 为 5 页规范结构，Excel 为真 .xlsx |
| 导入 | 侧栏上传 | TXT / MD / DOCX / 可复制文字的 PDF，上传后立即进入检索 |

**界面结构**（浏览器打开后可见）：

- **顶栏**：知识库状态（篇数 / 段数）、检索模式（语义检索已启用 / 关键词检索）、生成模型是否配置——打开就知道当前能力边界，不用猜。
- **主区**：四个页签（政策问答 / 四要素提取 / 多文件比较 / 跨期演变）→ 提问框 → 结果区。结果区自上而下是：状态与耗时、结论正文、四要素表、跨期时间轴、引用原文、导出条。
- **引用原文卡片**：编号 + 文件名（点击回看原文并高亮该片段）+ 章节 / 段落 / 片段 / 地区 / 规划期标签 + 相关度 + 正文摘录（可展开）+ 一键复制引用。
- **右栏**：知识库文件清单、导入新文件、以及「为什么可信」的设计说明。
- **细节**：⌘ / Ctrl + Enter 直接提交；窄屏自动变单列；打印时自动隐藏操作区，只留结论与证据（便于存 PDF 附在材料里）。

## 快速开始

**给不熟悉命令行的使用者（推荐）**：打开本文件夹 → 双击 `② 双击启动.command` → 等 5 秒，浏览器自动打开 `127.0.0.1:8765` → 在输入框里打字提问。不会操作就先双击 `① 先看这个（使用说明）.html`，里面有分步骤的大字图文。用完关掉那个黑窗口即可，下次再双击一次。

**给技术人员的命令行方式**：

```bash
cd ~/Desktop/管策智研10.28版
./配置并回填知识库.command     # 配置 → 建库 → 启动
# 打开 http://127.0.0.1:8765
```

没有模型密钥也能用：检索、溯源、四要素（规则整句抽取）、跨期对照、导出都正常，只是不生成综合结论，界面会明确标注。

向量检索是可选增强：想启用就双击 `配置嵌入密钥.command`，选一家服务商（**硅基流动 `BAAI/bge-m3` 模型不计费**，或阿里云百炼有 100 万 token 免费额度），粘贴密钥即可，脚本会自动备份、回填 33,039 条切片并核对。
注意：硅基流动要求**账户余额大于 0 才放行调用**（余额为 0 时连免费模型也返回 `402 Payment Required`），所以开户后需先充值让余额 > 0，模型本身不扣费。
也可以完全离线：`EMBEDDING_BASE_URL` 指向本机服务（如 `http://127.0.0.1:11434/v1`）时**不需要密钥**。不配则明确标为未启用（`semantic_active=false`），不会静默降级。详见 `部署与运维.md` 第四节。

## 质量指标（可复现）

```bash
python3 评测脚本.py    # 785 道官方训练题
python3 验收自检.py    # 端到端 30 项（自带库副本，不动交付库）
```

| 指标 | 结果 |
|---|---|
| 检索命中率（top-8） | **89.3%**（785 题纯词法，要求 ≥75%）；开启语义后抽样 120 题 **100%** |
| 完全覆盖率 / 首条命中 | 86.0% / 81.0% |
| 检索 P95 | 35 ms（纯词法）／3.9 s（开启语义） |
| 5 并发 | 全部成功，总墙钟 0.08 s（纯词法）／17.4 s（开启语义） |
| 端到端自检 | 30/30 通过（库副本 + 5 用户并发 + 向量状态自洽） |

分类别：A 93.9%、B 85.7%、C 85.2%、D 76.0%（均达标）。详见 `测试报告.md`。

## 设计要点

1. **证据优先，拒答兜底**：没有证据就明说「未找到」，不生成未经验证的文字。命中不到材料时返回状态而不是猜测。
2. **每句话都能点回去**：证据以「文件 · 章节 · 段落 · 片段」四元组定位，`/source/<planid>?frag=N` 直接定位高亮。
3. **引文锁定**：模型可以概括，但每条结论必须附一条**逐字引文**，引文必须能在对应原文里原样找到，否则丢弃——一次调用即可完成硬校验。
4. **元数据先行**：政策问题几乎都带地名和规划期，先用这两项把候选收窄，再排 BM25；这是命中率从 67% 提到 89% 的关键。
5. **切块服务于引用**：450–800 字一块，一段完整条款通常刚好一块，检索命中即可直接作引用原文。

## 访问控制

默认只监听 `127.0.0.1`。**绑定非回环地址时，缺令牌或没限流会直接拒绝启动**（退出码 2，不会先监听再提示）：
`ACCESS_TOKEN` 至少 16 位，`RATE_LIMIT_PER_MIN` 必须大于 0。本机自用不需要任何令牌。

## 已知边界

- 全量 53,161 篇（约 260 万切片）未入库，当前为 506 篇示例数据；全量需要先解决 55–77 GB 原文的存储与清洗。
- 交付库**已含真实向量**：`BAAI/bge-m3`（1024 维）× 33,039 条全覆盖。但语义检索需要运行时也能算查询向量——交付包里没有 `.env`，首次启动若未配置嵌入接口，会如实标为未启用并退回关键词检索（`embedded` 仍是 33,039，`semantic_active=false`）。填同一模型的密钥即可恢复（硅基流动该模型不计费，但账户余额须 > 0，否则 `402`；`EMBEDDING_MODEL=BAAI/bge-m3`）；换模型必须先 `--reset-embeddings` 再回填。
- 全量场景（5 亿级切片）应改用 `sqlite-vec` / FAISS，当前是进程内暴力余弦。
- 扫描版 PDF 不做 OCR。
- 默认只监听本机；对外部署请设置 `ACCESS_TOKEN` 与 `RATE_LIMIT_PER_MIN`（见 `部署与运维.md`）。
